# 应用管理修复与优化迭代

日期：2026-10-08。范围为单工作区、单 Gateway 写入实例，保留文件、聊天、代码和任务的原生业务实现。

## 交付结果

| 阶段 | 实现与证据 |
| --- | --- |
| 管理基础与真实启停 | HTTP 加载应用目录，WebSocket 更新、重连和快照恢复后同步，连接中断时轮询；桌面、Dock、窗口和插件命令使用同一目录。owner/admin 管理，member/guest 只读；服务端校验角色和修订号。无上一版本回滚返回冲突且保持状态。 |
| 完整包与持久化 | 完整 ZIP 包、SHA-256 清单和 Ed25519 签名；检查、权限确认、候选沙箱握手后提交。不可变版本目录和 SQLite schema 10 独立插件注册表；安装失败、数据库写入失败和并发冲突保持已提交版本。回滚恢复资源、manifest、权限和启用状态。 |
| 运行链路 | 官方入口打开真实原生窗口；外部入口打开 opaque-origin 沙箱。短期资源票据、Gateway CSP、宿主 frame-src、nonce/version/protocol 握手和 MessageChannel；SDK 提供用户、权限、资源读取/列表、过滤事件、命令和通知。 |
| 页面与交付 | 搜索、来源/状态筛选、详情、权限确认、签名与故障原因、上一版本及 traceId；桌面/移动端浏览器验收、Windows 便携 HTTPS 验收、跨目录恢复和 Windows/Linux CI 接入。 |

官方 `files.core`、`chat.core`、`code.workbench`、`runner.exec` 只提供启用、停用和打开，版本随主程序发布。系统状态、设置、应用管理和管理后台不可通过插件管理停用。外部插件以 `plugin:<完整 ID>` 注册，不能覆盖官方或系统入口；卸载保留业务数据和版本资源，可重新安装。

停用撤销启动入口、命令、RPC 和窗口。文件/聊天引用等共享业务接口继续可用，已发出的业务写入可以完成。代码、聊天文字、附件引用和未提交代码片段在界面卸载前保存；浏览器存储拒绝写入时使用会话内草稿。代码恢复上次选择的文件，避免停用后重新排序切到别的文件而看不到已有草稿。文件上传暂停并保留服务端会话，重新启用后可以继续；原始 File 对象只在当前页面会话内保留，刷新后需重新选择原文件。

Runner 状态与插件资源健康分别展示。关闭 Runner 不影响查看代码、编辑文件或展示任务历史。一个窗口加载或握手失败只影响该窗口；只有服务端确认资源字节缺失或损坏，才尝试恢复可用上一版本并标记故障。

## 数据迁移与恢复

schema 10 将旧插件记录一次性迁入独立 `plugin_registry`，保留启停状态。缺少完整包的外部旧记录标为待修复；启动扫描不能覆盖已提交安装。包资源按完整 ID、版本和清单摘要存入 `data/plugins/`，数据库不保存源机器的绝对资源路径。

日常 Gateway 由现有开发启动器在编译成功后热重载，完成 schema 9 → 10 迁移。迁移前自动生成 `.local/linkos/backups/before-migration-20261008T103556.816352000.tar.gz`。前后核对保留了消息、代码内容/版本及插件启停状态；服务启动导致项目资源的更新时间变化。

完整归档包含注册表、当前/上一版本资源、未完成上传和受信公钥。恢复旧配置插件目录时使用目标 `data/plugin-source`，与不可变包目录分开。恢复后仍能读取当前版本并回滚到相符的旧资源字节。较旧程序不能忽略新数据库版本直接启动；不兼容降级必须恢复升级前完整备份。

## 首期边界

- 外部包只支持 API `1.0`、包内 HTML UI 和 `network.mode=deny`。不开放 service、Runner、资源写入、任务执行或任意 URL 代理。
- RPC 和事件读取受用户角色、插件权限声明和资源 ACL 共同限制；私聊成员关系在服务端校验。事件仅提供获准的精简元数据，不转发整个工作区流。
- 握手/RPC 超时 5 秒，消息上限按 UTF-8 字节计算为 64 KiB；服务端限每用户/插件每秒 30 次、并发 8 次。窗口关闭或版本变化时释放端口、请求、命令和订阅。
- 沙箱限制同源、网络和宿主能力，没有 CPU 配额。切换 Gateway 后刷新页面重建宿主 frame-src 策略。

包制作和 SDK 示例见 [插件开发手册](../plugin-development.md)，部署和维护见 [部署手册](../deployment.md)。
