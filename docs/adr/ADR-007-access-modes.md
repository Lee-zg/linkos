# ADR-007：三种访问模式与管理后台审批

- 状态：开发态已实现，生产方案待定
- 日期：2026-09-01
- 关联任务：入网与身份、RBAC 与审计、ADR-006 会话边界

## 背景

ADR-006 建立了开发态会话边界：任何人都能通过 `POST /api/v1/sessions` 自取 `member` 会话，前端静默自动签发。产品要求把"谁能进入工作区"变成管理员可配置、可审计的能力：支持登录访问、匿名申请访问（审批制）和完全匿名访问三种模式，并提供管理后台进行模式切换与访问记录审批。

## 决策

在 ADR-006 的会话边界上扩展，不引入持久化：

- **三种访问模式**，由 `accessPolicy` 两个开关控制（内存态，默认全关，仅登录）：
  - 登录访问：恒开。访客在闸门输入显示名建立具名会话；口令与 `LINKOS_ADMIN_PASSCODE`（默认开发值 `linkos-admin`）匹配时角色为 `admin`，口令错误直接拒绝，避免误降级。
  - 匿名申请访问：`allowAnonymousApplication` 开启时可用。会话以 `pending` 状态签发，`requireActive` 中间件拦截一切业务路由（含 WebSocket）；管理员审批通过后同用户的会话状态同步置为 `active`。
  - 完全匿名访问：`allowFullAnonymous` 开启时可用。访客直接获得 `active` 的 `guest` 会话（显示名自动生成"访客-xxxxxx"），无申请流程；此时前端闸门隐藏申请表单。
- **访问记录**：每次会话签发产生一条 `accessRecord`（访问类型、状态、申请说明、来源地址、审批人/时间），`GET /api/v1/admin/access-records` 按创建时间倒序返回；审批仅允许从 `pending` 转移，重复同向审批幂等。
- **管理后台**：`requireAdmin` 中间件校验 `admin` 角色；策略读写、记录列表、审批动作全部挂在其后。策略与审批变更经事件总线广播（`access.record.created/approved/rejected`、`access.policy.updated`），管理界面实时刷新并以 10 秒轮询兜底。
- **前端闸门**：进入桌面前必须持有 `active` 会话；待审批页面每 3 秒轮询 `GET /api/v1/me`。会话令牌持久化在 `localStorage`，刷新后可恢复；会话不再静默签发。
- **权限范围**：匿名通过者与完全匿名访客当前与成员同权，仅不可见管理后台。后续在后台权限管理中细化。
- 会话仍为内存态、1 小时有效、重启即失效（同 ADR-006 的 PoC 约束）。

## 未决事项

- 访问策略与访问记录持久化（随 SQLite 迁移）。
- 管理员口令的正式凭据方案（邀请码、账户体系、轮换），生产部署前必须替换默认口令。
- 访客/匿名角色的资源级权限矩阵（当前与成员同权）。
- 审批的审计不可抵赖记录与通知渠道。

## 验收

- 策略关闭时匿名申请与完全匿名请求返回 `403 ACCESS_DENIED`；开启后分别得到 `pending` 与 `active` 会话。
- `pending`/`rejected` 会话访问业务路由分别返回 `403 ACCESS_PENDING`/`ACCESS_REJECTED`；审批通过后放行。
- 非管理员访问 `/api/v1/admin/*` 返回 `403 FORBIDDEN`，无会话返回 `401 AUTH_REQUIRED`。
- 前端闸门覆盖登录、申请等待、被拒绝、访客直入与网关离线五种界面状态；管理后台可切换策略、审批记录并实时刷新。
